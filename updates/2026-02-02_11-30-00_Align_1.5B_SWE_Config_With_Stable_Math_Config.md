## Rationale
The 1.5B math config has proven to be stable and reliable in production. This update aligns the SWE config with the same stability-enhancing settings while preserving SWE-specific requirements:

1. **Stability**: The math config's settings (larger batch sizes, dynamic batching, disabled prefix caching) have shown better training stability and fewer OOM issues.

2. **Throughput**: Increased GPU memory utilization (0.6 → 0.9) and dynamic batching improve training throughput without compromising stability.

3. **Memory Management**: Ulysses sequence parallel and optimized token lengths (34816) enable better handling of long contexts common in SWE tasks.

4. **SWE-Specific Preservation**: Key SWE requirements are maintained:
   - 16 rollouts per prompt (vs 8 for math)
   - temperature=1.0 for both training and validation
   - max_prompt_length=16384, max_response_length=16384

5. **Error Visibility**: HYDRA_FULL_ERROR=1 provides better error messages for debugging.

## Technical Details
- **Loss Aggregation**: `seq-mean-token-sum-norm` provides more stable gradients by normalizing token-level losses across sequences
- **Dynamic Batching**: Automatically adjusts batch sizes based on sequence lengths, improving GPU utilization
- **Ulysses Sequence Parallel**: Splits long sequences across GPUs, enabling efficient processing of 16K+ token contexts
- **Prefix Caching**: Disabled to avoid potential cache invalidation issues that can cause training instabilities
- **Tensor Parallelism**: Reduced from 2 to 1 to simplify communication patterns and improve stability on smaller models (1.5B)
